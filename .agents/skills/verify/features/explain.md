# Explainer

A reviewer receives three artifacts from one checked storyboard: infographic.png, video.mp4, and page.html.
Original source evidence and map.json remain internal records. The walkthrough, public map, and card are removed.

## Drive the real entry point

Run `prc explain` with a pinned source, authored board, Kokoro voice, and a candidate supplied through `--infographic`.
Use the current fixture infographic generated by the release checks for fixture runs.
Require `check_passed: true` and all three nonempty product artifacts.
Require the infographic verdict and published hash in run.json to match the exact published bytes.
A build without a passing infographic must fail. It is not a complete review aid.

Run `scripts/verify_page.py --page <exact page.html> --shots <new proof directory>`.
Require PASS for every scene, code hunk, previous/next, keyboard controls, narration, auto-advance, infographic, and coverage disclosure.
Inspect the screenshots. Verify the output hashes in report.json before handoff.
Probe the MP4 for 1920 by 1080, 30 fps, positive duration, and an audible stream.
Run `prc listen <output directory>` and require the current Parakeet or fallback recognizer plus planted controls to pass.
Inspect decoded video frames from the exact video.

Repeat stored-source generation with `--map` and the matching pinned `--git-dir`.
Require `map_source: stored` and identical source revisions.
Reject invalid receipt boards through the real CLI and preserve their failure records.
Run `bash scripts/verify-release.sh` before release readiness claims.

## Limits

Receipt checks establish quoted source, not every narration claim.
Inspect each infographic arrow's direction, endpoint, dash pattern, and extra connectors yourself.
The geometric gate establishes connecting ink only.
Silent `--voice none` is supported for local previews. Study and release narration must use Kokoro.
An analysis without a board can write internal evidence. It cannot satisfy the three-artifact study gate.
