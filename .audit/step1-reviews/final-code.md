## New minor finding (not a blocker)

**`_read_mode` crashes on non-UTF-8 tesseract stderr.** src/prc/presentation/infographic.py:450-456 runs tesseract with `capture_output=True, text=True` and catches only `OSError, subprocess.SubprocessError`. Decoding the tool's stderr/stdout raises `UnicodeDecodeError` (a ValueError) inside `subprocess.communicate`, which escapes `_read_mode` and `gate` and aborts the whole explain run instead of recording a failed mode. Reproduced while probing: a corrupt PNG made the real tesseract write a non-UTF-8 byte (0x89) into stderr and the gate raised `UnicodeDecodeError` at ._translate_newlines instead of returning verdict `tool` with a failure record, which is what the triage's defect-3 fix otherwise promises. Suggested one-line fix: catch `UnicodeDecodeError` there (or decode with errors="replace").

Small strictness note, by design: a code token tesseract refuses to join in all four readings fails the gate even if humans see no space (fail closed). D23 documents exactness for code tokens; acceptance-history prose in D23 covers the false-rejection tradeoff.
