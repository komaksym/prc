# Design synthesis

Product scope is accepted. The renewed bounded [critical-only closure](../work/critical-only-loop.md) completed after one fix cycle with three clean fresh reviews and a separate verifier reporting zero verified criticals. All six original mechanisms are closed. Implementation remains at the user's checkpoint.

The MVP is a GitHub-first comprehension layer for a human reviewing an AI-generated PR. It provides a concise overview, evidence links, a required infographic, and additional artifacts selected from the change. Video remains deferred. It helps the reviewer understand a change and its risks; the human owns approval, rejection, or requests for changes.

Trusted acquisition establishes Code Comparison Identity from repository, PR, pinned head, observed target-base tip, and comparison or merge-base. Each check separately retains its actual execution subject, run and attempt, consumed payload hashes, scope, and eligibility. Missing or conflicting provenance becomes a gap. Source Basis Identity includes the complete selected source-and-evidence basis, metadata, verification eligibility, trace, and policy versions. Source Snapshot additionally binds the mechanical Git-tree inventory, Semantic Input Manifest, and analysis policies. Late context discovery expands the manifest and restarts analysis under a new snapshot.

Acquisition captures timed resource observations and checks membership and version drift with at most three attempts. Matching reads establish observational stability, not an atomic GitHub transaction. Missing observations or unresolved drift make consistency unknown. At presentation and decision recording, the controller reconciles full Source Basis Identity and required-result expiry. The UI shows last-observed matching, stale, or unknown with a finite freshness deadline. Local compare-and-swap protects exact snapshot and view attribution. It does not lock GitHub or authorize an atomic live merge.

Generator and validator results both remain untrusted. Deterministic checks enforce bindings, scope, and mechanically checkable obligations. Other semantics carry visibly model-assessed support, evidence, limitations, and uncertainty. Independent assessment does not prove truth or immunity to hostile input. Disagreement or failed obligations produces inference or a gap. Coverage is many-to-many with residual state and independent closure falsification; mechanical inventory completeness does not prove complete semantic understanding.

All presentation paths use inert source data, trusted templates, validated semantic operators, restricted links, and controlled resources. Labels, relationships, emphasis, and epistemic markers reference semantic IDs. Output structure is checked before hashing; a PublishedViewIdentity records semantic artifact, renderer and presentation versions, and concrete rendered content. Reviewer state binds to that exact view and snapshot. Semantic analysis is recomputed when snapshot identity changes, and publication is atomically canonicalized under its complete input key.

The [Solo evaluation protocol](../work/critical-only/evaluation-protocol.md) freezes a 12-pair creator-only pilot with three adjudicated questions per snapshot, treatment identities, assignment, scoring, paired estimation, uncertainty, success criteria, and failure handling. Baseline, product, instrument, and fallback consume the same captured evidence bundle. Product failures retain assignment and use frozen fallback; missing outcomes stay in primary and sensitivity analyses. Accuracy on the instrument is primary, time secondary, and confidence diagnostic. The pilot provides an exploratory solo signal without a claim about all developers or complete PR understanding.
